# Игра на жизнях и рейтинг гостей

## Что входит

- `index.html` — ваш исходный экран ввода имени, сохранён без изменений.
- `index_old.html` — приглашение с переходом к анкете.
- `wishes.html` — анкета; после подтверждённой записи получает доступ к игре для указанного гостя.
- `game.html` — игра на 5 жизней с отправкой результата.
- `Code.gs` — обновлённый Google Apps Script для анкеты, результатов и рейтинга.

## Обновление сайта

1. Разместите четыре HTML-файла рядом, сохранив эти имена. Сохраните существующую папку `assets`; фотографии и музыка не входят в архив.
2. Полностью замените старый код в Google Apps Script содержимым нового `Code.gs`.
3. Сохраните код и выполните `setupRsvp`. Будут подготовлены существующий RSVP и новые листы GameAttempts и GameLeaderboard. Функция не добавляет тестовых гостей.
4. В «Развернуть → Управление развертываниями» отредактируйте существующее веб-приложение: выберите новую версию и разверните её. Адрес существующего развёртывания сохраняется.
5. Загрузите свежую страницу, отправьте анкету и сыграйте до завершения. Новая анкета должна выдать игре доступ: старый обработчик без обновления не умеет записывать очки.

Доступ к рейтинговой игре выдаётся после успешной отправки анкеты. Гостям, которые отправляли её до этого обновления, нужно отправить её ещё раз. При OVERWRITE_BY_NAME=true строка RSVP обновится по прежним правилам, без новой строки для того же нормализованного ФИО.

## Правила

- В начале 5 жизней, таймера окончания нет.
- Пойманный цветок: +1 очко. Пойманное кольцо: +3 очка.
- Любой предмет, ушедший за нижний край поля, отнимает ровно 1 жизнь.
- После пятого пропуска раунд заканчивается. Дальнейшие предметы не начисляют очки и не уменьшают жизни ниже нуля.
- Скорость постепенно повышается до заданного предела. Частота появления одинаковая — один предмет каждые 0,62 секунды.
- Пауза сохраняет жизни и очки. Переключение вкладки и большой сбой частоты кадров автоматически ставят игру на паузу.
- Управление: мышь, стрелки клавиатуры, касание поля или кнопки со стрелками.
- Попыток может быть несколько, в рейтинге учитывается лучшая. Меньший результат не снижает рекорд.
- При равенстве рекордов гости делят место; для единственного победителя можно провести переигровку.

## Где выбрать победителя

**GameLeaderboard** автоматически сортируется по лучшему результату:

| Столбец | Значение |
| --- | --- |
| Место | Текущее место, одинаковое при равных очках |
| Имя, Фамилия | Гость из отправленной анкеты |
| Лучший результат | Максимум очков за все сохранённые попытки |
| Попыток | Число сохранённых завершённых раундов |
| Дата рекорда | Время сохранения лучшей попытки |
| Последний результат | Очки последней сохранённой попытки |
| guestKey | Служебный ключ гостя |

Победитель — гость с местом 1; если таких несколько, результаты равны. Место в игре показывается на момент записи и может измениться после новых попыток других гостей.

**GameAttempts** — журнал всех завершённых попыток: имя, фамилия, очки, пойманные цветы и кольца, пропуски, длительность активной игры и служебные поля. Длительность нужна для проверки корректности, она не ограничивает раунд и не влияет на место.

Рейтинг пересобирается из журнала при каждой записи, включая повторную отправку. Его первые восемь столбцов управляются скриптом. Для ручных пометок о выдаче призов используйте отдельный лист, чтобы пометки не сместились при изменении порядка участников.

## Сохранение и ограничения

- В интерфейсе указано имя текущего игрока. Результат записывается после окончания раунда, а не во время паузы или закрытия страницы.
- Сервер выдаёт подписанный доступ по данным анкеты и отдельный идентификатор раунда. Имя для записи берётся из подписанных данных, а не из полей запроса с очками.
- Сервер проверяет арифметику очков, пять пропусков, версию игры, число предметов и длительность относительно старта раунда.
- Повтор того же результата не создаёт второй попытки. Изменённый результат с тем же идентификатором отклоняется.
- Если сеть пропала, доступна повторная отправка. Новый раунд начинается после подтверждения предыдущего. Неотправленная попытка сохраняется на устройстве, когда доступно хранилище; иначе она остаётся только в открытой странице. Закрытие этой страницы при недоступном хранилище потеряет неподтверждённый результат.
- Доступ игрока действует 30 дней; отправить завершённый раунд можно в течение 7 дней после его начала.
- Публичной выдачи списка гостей и результатов через doGet нет. Организатор смотрит рейтинг в своей Google Таблице.
- Как и прежде, одинаковые нормализованные имя и фамилия считаются одним гостем. Для полных тёзок нужны отдельные идентификаторы приглашений.
- Это базовая защита для дружеского конкурса, а не полноценная защита от мошенничества: ввод ФИО не проверяет личность, а итоговые игровые данные вычисляет браузер. Намеренно подделанный, но правдоподобный результат может пройти проверки. Для строгого конкурса нужна серверная проверка последовательности игры или финальная переигровка при организаторе.

Не меняйте и не публикуйте `WEDDING_GAME_SECRET` из свойств скрипта: он создаётся автоматически и нужен для проверки выданных доступов. Его замена сделает старые доступы недействительными.

## Проверки

Пройдены 19 сценариев серверной части, 10 сценариев игры (включая полный прогон клиента через имитацию Apps Script) и 23 регрессионных сценария RSVP. Проверены подписи, идентификация гостя, жизни, очки, рейтинг, равные результаты, сохранение рекорда, восстановление после ошибки, повторные отправки и совместимость старого отказа от участия.

Проверены относительные ссылки четырёх страниц и точное совпадение входного index.html с последним приложенным файлом. Реальные записи в вашу Google Таблицу и визуальная проверка в браузере не выполнялись.
